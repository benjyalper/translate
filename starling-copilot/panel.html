      ℹ️ How assisted (tagged) segments work
      

        
Some segments contain real inline tags — the yellow ①② markers in Starling. Typing over the whole cell would destroy those tag objects, so the extension never auto-writes them. They're marked ✋ paste by hand in the review.

        
It still proofreads / translates them for you, and when a segment is a bullet list (A • B • C — each item wrapped in its own ①…① pair) it splits the corrected text into numbered parts.

        
To apply one:

        
    
          
  1. Click Copy on a part (its badge number matches the tag number in Starling).
    2. 
          
  2. In the Starling cell, select only the text between that part's ①…① tags.
    3. 
          
  3. Paste. The tag objects stay exactly where they were — you only replaced the text.
    4. 
        

        
Everything without tags is still written automatically in step 4. This keeps the fragile tag surgery in your hands (reliable) while the extension does all the mechanical work around it.

        ℹ️ How Feishu LQA works
        

          
The task owners ran a global AI translation check and listed suspected errors in a Feishu sheet. For each row you decide whether the AI-flagged error is valid (real → fix it in Starling) or invalid (false positive).

          
Feishu sheets are drawn on a <canvas> — the cells aren't real HTML, so this can't scrape them. Instead you paste the rows (Ctrl+C copies them as tab-separated text) and it runs gpt-5.4 per row.

          
It fills the sheet's 5 Linguists columns:

          
    
            
  1. Valid (Yes/No) — is the AI error real.
    2. 
            
  2. Category — one of the sheet's 9 error types, only when Valid = Yes.
    3. 
            
  3. Final Translation — the corrected Hebrew, only for valid issues.
    4. 
            
  4. Updated on Starling — left blank; you tick this as you apply each fix.
    5. 
            
  5. Comments — the invalid reason, only for invalid spelling/grammar errors, one per type (deduped, per the task email).
    6. 
          

          
Runs locally with your OpenAI key. Only the text columns go to GPT — the Feishu doc never leaves this browser. Keep shared-account credentials out.

        ℹ️ How Sheet → Starling works
        

          
This drives the manual write-back: for each valid fix it filters Starling's All tasks by Key (en→he), you open the task, and it reads the live segment, writes the Final Translation, and proofread-confirms that one row.

          
It never blind-pastes. A key can live in several tasks, a task's source can differ from the sheet's, and a task comment can overrule the sheet — so it always shows you live source vs. sheet source and current target vs. final before you approve each write. It guards on source-match and skips rows that already match.

          
    
            
  1. Search — filters All tasks to the key (hard reload) and auto-opens it when exactly one task matches; if several match, it reports the count and you open the right one with 👁.
    2. 
            
  2. Check — reads the live segment; flags source mismatch / already-correct.
    3. 
            
  3. Write + confirm — types the Final Translation and ticks proofread ✓✓.
    4. 
          

          
Stops at confirmed — you resubmit the task in Starling. Only TikTok source/target text is used; no Feishu doc or shared credential is sent anywhere.

        ℹ️ How Crowdin works
        

          
Harvest lists the file's source strings via the official API (GET /projects/<id>/strings) plus their current Hebrew. GPT-5.4 proposes a translation per string. Enter posts it (POST /projects/<id>/translations, unapproved) so it appears in the editor for you.

          
The tool never approves/submits — you do the final approve in the Crowdin editor. Only the source text is sent to OpenAI; your Crowdin token only talks to api.crowdin.com.

        ℹ️ How memoQ works
        

          
Harvest reads every segment through memoQ's editor API (POST …/docs/<id>/rows) — source, current Hebrew, inline tags, and confirmed status — in your logged-in session. GPT-5.4 proposes a translation per segment. Write saves it to the segment's target (PUT …/rows/<id>) as an unconfirmed draft.

          
The tool never confirms/delivers — you confirm each segment in memoQ. Inline tags are round-tripped exactly; if GPT drops a tag, that segment is refused (write it by hand) rather than saved wrong. Only source/target text is sent to OpenAI.

        ℹ️ How YiCAT works
        

          
Harvest reads every segment through YiCAT's segment API (GET …/cat/segment?…&seg_range=1-N) — source, current Hebrew, real inline placeholder tags, and confirmed status — in your logged-in session. The cosmetic whole-segment <g1> style wrapper is stripped and not treated as a tag. GPT-5.4 proposes a translation per segment.

          
The default is copy — you paste each proposal into the target cell and confirm it yourself. The auto-write drives YiCAT's own in-cell editor (Tiptap) and reads the cell back to verify — it reports failure rather than claiming a write it can't confirm. By default it writes a tracked change (old struck out, new marked inserted, exactly like manual editing); if that can't be verified it safely falls back to a plain untracked write. It skips segments with real tags and never confirms/delivers. Only source/target text is sent to OpenAI.
