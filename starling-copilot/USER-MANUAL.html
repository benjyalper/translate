User Manual

Turn your finished work into the translations you get next time.

A Chrome side-panel that harvests a CAT task's segments, proposes Hebrew with GPT guided by your accumulated knowledge, lets you review, and writes the approved text back — across the Starling String and Document editors.

Current · content-script v40 Editors String + Document Never auto-submits
Nothing here ever auto-submits a task. Submit is always a separate, deliberate click — and the only one-click submit (⚡ Write·Confirm·Submit) asks once before it does anything.

01 The mental model

The copilot's intelligence is six stores. Five are hand-curated "brains"; one is a read-only history mined from your finished work. Learn what each does and when it acts, and the tool stops being a black box.

StoreWhat it holdsWhen it acts
🧠 Style BrainHouse rules + a glossary (advisory EN→HE)Injected into the GPT prompt — shapes what GPT writes
🧩 Consistency memoryEvery source you've written → the exact Hebrew you usedAfter GPT — swaps in your prior wording so identical sources stay identical
🔒 Locked termsMandatory EN→HE pairs (non-negotiable)In the prompt and as a post-check flag — outranks everything
🩹 Auto-fixDeterministic HE→HE find-and-replace rulesAfter GPT — mechanical corrections (plural imperative → your slash form)
＃ Plural memoryRemembered CLDR form-sets (one/two/many/other)Pre-fills the 🔢 Plurals tool so it doesn't re-ask GPT
🏷 Term baseStarling's own inline term references (soft hints)Injected per-segment into the prompt; flagged on deviation
📦 CorpusA concordance mined from all your Submitted tasksFeeds 🔎 Lookup & learning; you promote from it — never edits live

How a translation is actually decided

Every time you press ✨ Run, each segment flows through this exact order. Knowing the order tells you who wins when two brains disagree:

1. GPT proposes Hebrew         ← guided by Style Brain + Locked terms + Term base (in the prompt)
2. Consistency memory applied  ← if you've written this source before, your wording replaces GPT's
3. Auto-fix applied            ← deterministic HE rewrites run on the result
4. Locked-term post-check      ← flags any segment missing a mandatory term (never auto-edits)
5. Consistency + term-base checks ← flag in-task drift / missing term Hebrew (never auto-edit)
   → the Review list, with badges telling you what happened to each row
6. You review / edit / approve  (optional: 🧹 Sweep drift for a deeper consistency pass)
7. Write to Starling → each written segment is REMEMBERED (feeds step 2 next time)
Precedence in one line: 🔒 Locked > 🧩 Memory > 🩹 Auto-fix > GPT, with the glossary and term base as advice GPT usually follows but can inflect. The 📦 Corpus never edits anything live — it's history you consult and promote from.

02 Workflows

The tool rewards a rhythm. Do the per-task loop well, keep the corpus fresh, and periodically fold your finished work back into the brains — each cycle makes the next batch of suggestions closer to what you'd write by hand.

Per task

Open the task in Starling (String or Document editor), then run the flow top to bottom. This same order is printed on the 📋 Per-task workflow card at the top of the 🐦 Starling tab.

🏷 Grab term base
Read the task's approved terms first, so GPT uses them. In the 🏷 Term base card.
2 · load
⬇ Harvest
Pull the task's segments into Review. Step 1.
3 · gpt
✨ Run
Proofread or translate through the full pipeline. Step 2.
4 · unify
🧹 Sweep drift
Optional: catch a word rendered two ways, then review & edit. Step 3.
5 · write
↩ Write approved
Type the approved targets back (or ⚡ Write·Confirm·Submit). Step 4.
On a Document editor task, keep that editor tab open and active — 🏷 Grab, ⬇ Harvest, and the write-back verification all read the open editor's own data directly. Pasting a bare task id works for String-editor tasks; doc tasks need the live tab.

The cadences

Daily

Keep the corpus current, finish cleanly

Two habits stop knowledge from going stale:

  1. Once at the start (with a starling.bytedance.com tab open), click ⟳ Update — add new Submitted so yesterday's submitted tasks enter the 📦 Corpus. The badge tells you how many are new.
  2. As you finish each task, use the per-task loop above and ↩ Write approved — every written segment is remembered, so tomorrow's identical sources fill in automatically.
Weekly

Fold finished work into the brains

Turn a week of accepted wording into signal the tool acts on:

  1. 📚 Learn from a task (Style Brain card) — open a submitted task, ⬇ Harvest, then ➕ Add pairs to memory and/or 🧠 Distill rules & terms. Works on String and Document tasks.
  2. Clear the ⚠ Conflicts queue — decide any clash the week parked instead of overwriting.
  3. If the glossary drifted, run 🔤 Phrase mining on the corpus and promote the reliable terms.
Monthly

Tighten, back up, get paid

  1. 🧹 Consolidate rules — one GPT pass merges duplicate house rules and tightens wording. A bloated ruleset gets skimmed by GPT and costs more to send every batch; a tight one is actually followed. A backup downloads first; nothing changes until you click Replace.
  2. 🗄 Backup all brains — one JSON snapshot of every store and the corpus. Keep these.
  3. 💰 Word count — set Tasks = Submitted, pick your first-submitted date column, and read the month table for pay.
  4. Occasionally, tick Rebuild from scratch and 📦 Build corpus to re-read everything clean.
Whole-corpus

Learn from everything at once

When you want the biggest jump — usually after a big backlog is submitted:

  1. 📦 Build / ⟳ Update the corpus so it covers every Submitted task (String and Document — see the note below).
  2. 📚 Learn from whole corpus — one GPT pass over every pair extrapolates rules, terms, expressions & exceptions, reads a source's evolution newest-first so it learns the correction rather than both versions, then reconciles against your current brain. Findings land in the 🧠 review list; a full backup downloads before you can merge.
  3. Promote to memory the ✅ consistent pairs, and 🔒 Lock the reliable terms.

Every path feeds the acting brains, so the same correction never has to be made twice:

If a doc-task write ever shows "wrote N but couldn't verify", that warning is now correct only when the text genuinely didn't land — v40 verifies doc writes from the editor. If in doubt, reload the tab (Ctrl+R) and eyeball the cells, or use ⚡ Write·Confirm·Submit, which confirms each segment.

05 Lookup — "how do I normally translate this?"

Type ≥2 characters (English or Hebrew) to see how a word or phrase is handled across all six stores at once. It reads only — it changes nothing.

  • 📦 Corpus — the richest signal. A stats bar of every Hebrew rendering and its % share, then example pairs, each with a ↗ task button that opens the real Starling task it came from.
  • 🧩 Memory · 🧠 Glossary / 🔒 Locked · 🩹 Auto-fix — exact and near matches from each brain.

The corpus stats bar

family pairing → in 24 segment(s) · 11 task(s)
  חיבור משפחתי   ████████████  55% · 13
  קישור משפחה    ██████        30% · 7
  צימוד למשפחה   ██             8% · 2

% is the share of all occurrences. Forms differing only by a leading clitic (ו ב ה ל כ מ ש) fold into one variant — data-driven, not blind stripping — so the definite ה of המשפחה folds to משפחה, but a root מ never seen stripped is left alone.

Set your preferred translation

For English queries, a preferred Hebrew field (pre-filled with the dominant surface) offers ➕ Glossary (advisory — GPT prefers and inflects it) and 🔒 Lock (mandatory — flagged if missing). Both apply going forward only; a clash is reported, never silently overwritten.

06 Style Brain — rules + glossary

Advice injected into the GPT prompt. It's how you teach tone, register, and preferred terminology so GPT writes the way you would. It steers GPT — it doesn't mechanically edit output (that's Auto-fix).

ButtonWhat it does
Distill & reviewGPT extracts generalizable rules + term pairs from ingested source text, shown for you to merge.

➕ Add rule / Add termOne free-text house rule, or one advisory EN→HE pair, straight in — no GPT.

📚 Learn from a Starling task

Turns a finished, proofread-confirmed task into training signal — your confirmed pairs are the best data because they're your accepted wording. ⬇ Harvest reads the pairs; ➕ Add pairs to memory drops them into 🧩 memory; 🧠 Distill generalizes rules/terms. Anything that clashes goes to ⚠ Conflicts.

Learn-from-task now reads the Document editor too — for a doc task it reads the open editor's data directly, so keep that tab open.

07 Consistency memory — "same source, same Hebrew"

Every segment you write is remembered as source → the exact Hebrew you used. Next time that identical source appears, your prior wording fills in. This is the store that acts after GPT (pipeline step 2).

If GPT proposes something different from memory, that row is left unchecked and badged 🧠 memory — review, so you confirm deliberately. A remembered mistake never re-applies silently — writing a corrected version overwrites the memory.

ControlWhat it does
Apply remembered wording (toggle)Master switch. Default off (data kept, not applied). On = your wording replaces GPT's on exact-source matches, and identical sources in one task are aligned.
🧠 Suggest near-matches (fuzzy) + thresholdWhen there's no exact match, offer the closest prior translations (Dice ≥ threshold, default 80%). Review-only — a use button appears; nothing auto-applies.
➕ Remember · Export · ClearStore a pair manually; back up; or wipe (password-gated).

When the same full source repeats in one task, all rows are aligned to one Hebrew by majority vote (memory outranks the vote; ties → earliest), badged 🧠 same-as-above.

08 Locked terms — the mandatory glossary

EN→HE pairs that outrank every other store. Enforced two ways: in the prompt each term is non-negotiable (GPT may only add a Hebrew prefix and inflect); and after a Run, any segment whose source has the term but whose target is missing the required Hebrew gets a red 🔒 locked term badge. It never auto-edits — you fix the row by hand and the flag clears live (the match tolerates a fused prefix and the definite-ה drop).

Locked beats memory. If a stale remembered target would violate a locked term, the locked term wins and the clash is parked in ⚠ Conflicts.

Glossary vs Locked? Glossary = advisory (GPT prefers and inflects freely — good for slash forms). Locked = mandatory (flags any run missing it — good for brand names and fixed terminology that must never drift).

09 Auto-fix — deterministic HE rewrites

A curated dictionary of Hebrew find-and-replace rules applied to every target after GPT (pipeline step 3). It's a dictionary, not morphology, because Hebrew imperatives are irregular — you lock in both sides so each fix is correct by construction (שלמו → שלם/י, נסו → נסה/י).

  • Whole-word (Hebrew-boundary) match; an optional leading ו is preserved (והצטרפו → והצטרף/י).
  • Every change is badged ✎ auto-fixed and reverts if you edit the text.

Controls: master toggle, Add rule (from → to), Export, Clear (password-gated).

10 Term base — Starling's own inline terms

Starling underlines source words that carry an approved term entry; the hover popover holds an EN→HE, a part-of-speech, and a DNT (do-not-translate) / Brand flag. ⬇ Grab term base reads every term in the open task and splits them into two tiers:

  • DNT / brand terms (e.g. TikTok) route into 🔒 Locked as keep-as-is (strict).
  • Translatable terms (e.g. content → תוכן) become soft hints: injected per-segment into the GPT prompt as the preferred rendering that may bend when grammar or context requires (a Noun used as a verb, "due to" → עקב), and surfaced as a 🏷 term review flag on deviation — never forced.
Grab works in both editors — in the String editor it scrolls the whole virtualized list; in the Document editor it reads the terms straight from the task data. A toggle turns the whole thing off for harvest/write.

11 Corpus — the concordance from your finished work

Batch-reads every Submitted task's proofread-confirmed segments — from the String and Document editors — and aggregates them: for each source it records the distinct target variants, how often each occurred, and across how many tasks. It's read-only history; building it never changes a live translation. It powers 🔎 Lookup, 🔤 Phrase mining, and 📚 whole-corpus learning.

🔤 Phrase mining & 📚 whole-corpus learning

🔤 Mine phrases scans the corpus for EN phrases you translate consistently (≥3 tasks, dominant rendering) vs. ones that drift, and proposes short terms to promote. 📚 Learn from whole corpus runs one GPT pass over every pair, reconciles it against your brain, and drops findings into the 🧠 review list. Both back up first; clashes become ⚠ Conflicts, never silent overwrites.

12 Conflicts to resolve

The single adjudication queue. Whenever two stores would disagree — a glossary/locked term mapping the same English to a different Hebrew, a remembered source gaining a second target, or a locked-vs-memory clash — nothing is silently overwritten. It's parked here as an orange card. The values are editable: fix the wording if neither side is quite right, then pick the side that wins; the other is removed. You always decide.

13 The Starling flow

The main mode. The brains above all feed in here. The 📋 Per-task workflow card at the top restates the order (§2).

Step 1 · Load segments

⬇ Harvest from this tab reads the open task's segments (virtualized rows included). The Only segments filter restricts to numbers/ranges (10-20, 5,8,12) or a term matching source/target/key (Family Pairing), mixable. You can also load an exported XLIFF for a reliable read; write-back still uses the live tab.

Step 2 · Process with GPT

Pick 📑 Proofread or 🌐 Translate, optionally include tagged rows / empty targets, then ✨ Run. GPT now also gets an internal-consistency instruction — it tries to render a recurring word the same way across the batch.

Step 3 · Review & approve

Click any Hebrew target to edit it — your edited text (badged ✎ edited) is what gets written, confirmed, and remembered. View filters: Changed · All · ✋ Paste by hand · 🧠 Memory–review · ⚖ Consistency · ⚖ Drift · 🏷 Term base.

Paste-by-hand: tag-aware splitting

Tagged segments (⚠ chip / tag) are never auto-written — typing over the cell would destroy the tag objects. The tool proofreads/translates them and splits the corrected text into the runs between the tags, each with a Copy button whose badge number matches the tag number. Select only the text between a part's ①…① tags and paste — the tags stay put. (Splitting now respects the real tag boundaries even when a bullet sits inside a tag.)

Step 4 · Write back & confirm

↩ Write approved types each approved, non-tagged target into its cell, then verifies it persisted (server re-read for String tasks; from the editor for Document tasks). Every written segment is remembered. ⚡ Write·Confirm·Submit writes, confirms, then submits in one go — an irreversible submit; it asks once.

Step ✓ / 5 · Confirm all · Submit · QA

✔ Confirm all confirms every row (ignoring normal QA, only Critical blocks); ➤ Submit task delivers it (irreversible); 📋 Read QA warnings reads Starling's own QA so you can clear it first. 🔢 Scan plurals handles CLDR form-sets, pre-filled from 📦 Plural memory.

14 Sweep drift — internal consistency

Two safeguards catch a word rendered two ways within one task:

  • ⚖ Consistency (automatic, deterministic) — after every Run, the tool builds a mini-glossary from standalone-label segments and flags any other segment using that term whose Hebrew doesn't match. Flag only; a 🔒 lock button promotes the pairing forever. Catches defined-label drift.
  • 🧹 Sweep drift (GPT, on demand) — one GPT pass over the whole task finds free lexical drift the deterministic check can't: the same verb or collocation rendered differently across differently-worded segments (e.g. "information" → מידע here, פרטים there).

Choosing the winner

Sweep drift doesn't pick for you. Each flagged row shows the ⚖ drift badge and one use ‹rendering› button per competing Hebrew rendering. Clicking one standardizes every segment in the task that uses that term on your choice — each rewritten grammatically (gender, number, prefixes adjust; nothing else changes). A keep current button sits alongside them: it dismisses the flag and leaves every segment's wording exactly as harvested — for when the drift is fine, or neither rendering is what you want. Review-only until you click.

Run 🧹 Sweep drift after you've settled the wording, since it reads the current targets. When you apply a rendering, glance at one rewritten row — GPT is regenerating the grammar around the swapped term.

15 Word count & pay

Reads your Starling My tasks list and sums the Weighted word count × your rate. Set Tasks (All / Submitted / In progress), pick a date column in By month of… (auto-detected, prefers a "first submitted" field), and 🔄 Compute from My Tasks renders totals, a status breakdown, and a monthly table. For "all tasks submitted per month," set Tasks = Submitted and read the month table.

16 Other CAT modes

The top row switches the host CAT tool. ⚖️ Feishu LQA, ↩ Sheet → Starling, 🌐 Crowdin, 🅜 memoQ, and 🐱 YiCAT each follow the same shape — connect / detect → harvest → GPT proposals → review → write / copy — and reuse all the same brains, so your terminology and style stay identical everywhere. Each has an ℹ️ How … works expander with its specifics. Feishu LQA additionally learns from your validated rows, closing the loop back into the brains.

17 Backups & restore

  • 🗄 Backup all brains (Corpus card) — one JSON with every store and the corpus. Keep these; a phrase-mining Promote auto-downloads one first, and Restore backs up the current state before overwriting.

19 Quick answers

How do finished tasks get into the corpus?

Submit them in Starling, then press ⟳ Update — add new Submitted (don't tick "Rebuild"). Optionally Promote via phrase mining or 📚 whole-corpus learning.

Why is a review row greyed out?

It's unchanged — GPT's suggestion already matches the cell. Switch to the Changed filter to hide these.

Memory vs Glossary vs Locked?

Memory = your exact past wording, applied after GPT. Glossary = advice GPT prefers and inflects. Locked = mandatory, outranks all and flags if missing.

My doc-task write said "couldn't verify" — did it save?

On v40 that warning is only shown when the text genuinely didn't land in the editor cell. Reload the tab and eyeball the cells to be sure; if some came back empty, re-run ↩ Write or use ⚡ Write·Confirm·Submit.

Will anything auto-submit?

No. Writing and confirming are separate from submitting, and submitting is always a deliberate click.
